SO4 publishes every release as a [JSON Feed 1.1](https://jsonfeed.org/version/1.1) document at [https://so4.market/feed.json](https://so4.market/feed.json). JSON Feed is a versioned, documented format with stable required fields — unlike the internal `changelog.json` render shape, which is an implementation detail of the `/changelog` page and may change at any time. Build integrations against `feed.json`, not `changelog.json`.

## Document fields

| Field | Type | Present | Meaning |
|---|---|---|---|
| `version` | string | always | `"https://jsonfeed.org/version/1.1"` |
| `title` | string | always | `"SO4 Market Releases"` |
| `home_page_url` | string | always | `https://so4.market/` |
| `feed_url` | string | always | `https://so4.market/feed.json` |
| `description` | string | always | Human summary of the feed |
| `language` | string | always | `"en"` |
| `items` | array | always | One item per release, newest first |

## Item fields

Every item carries the standard JSON Feed 1.1 fields:

- `id` — unique and permanent: the version anchor URL, e.g. `https://so4.market/changelog#v0-4-0`.
- `url` — same value as `id`; where a human reads the item.
- `title` — `"Version 0.4.0"`.
- `content_html` — the full release section rendered to HTML (inline markdown only: links, bold, italic, code).
- `date_published` — ISO 8601 timestamp built from the release date.

## The `_so4` extension

JSON Feed 1.1 allows namespaced extension fields prefixed with `_`. Ours is `_so4`, so consumers do not have to parse HTML to get structured data:

```json
"_so4": {
  "version": "0.4.0",
  "yanked": false,
  "breaking": false,
  "entries": [
    { "type": "added", "area": "trade", "pr": 512, "breaking": false }
  ]
}
```

| Field | Type | Meaning |
|---|---|---|
| `_so4.version` | string | SemVer of the release (`"0.4.0"`) |
| `_so4.yanked` | boolean | True if the release was yanked |
| `_so4.breaking` | boolean | True if **any** entry in the release is breaking |
| `_so4.entries` | array | Structured entries; empty array if the release has none |

Each entry in `_so4.entries`:

| Field | Type | Meaning |
|---|---|---|
| `type` | string enum | One of `added`, `changed`, `deprecated`, `removed`, `fixed`, `security` |
| `area` | string enum | Product area: `trade`, `pools`, `earn`, `referrals`, `faucet`, `wallet`, `docs`, `general`, `ci`, `internal` |
| `pr` | number \| null | GitHub pull request number, or null when there is no linked PR |
| `breaking` | boolean | True if this entry is a breaking change |

## Stability promise

- The `version` field pins the contract: a feed that says `1.1` validates against the [published JSON Feed 1.1 schema](https://github.com/jsonfeed/jsonfeed-validator), today and indefinitely.
- Existing top-level and item fields will not be removed or repurposed while the feed declares `1.1`. New fields may be added.
- `_so4` field types above are contractual. Additions are allowed; removals and type changes require a major announcement here.
- `id` values are permanent: once published, a version anchor never changes meaning.

## Generation

The feed is generated from the same parse pass over [`CHANGELOG.md`](https://github.com/SO4-Markets/interface/blob/main/CHANGELOG.md) that produces the site's `changelog.json` and `changelog.archive.json`, via `bun run changelog:build`. Regeneration is deterministic: two runs over an unchanged source produce byte-identical output.
